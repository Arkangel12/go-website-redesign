This guide covers mistakes that Go beginners and developers coming from other languages frequently make. Each section shows what's wrong, why it fails, and the correct approach.

Comparing a non-nil interface to nil

An interface value is only nil when both its type and value are nil. A typed nil pointer wrapped in an interface is not nil. 

// Wrong — logs false even though err looks "empty"
func getError() error {
    var p *MyError = nil
    return p          // returns an interface holding (*MyError, nil) — not nil!
}

err := getError()
fmt.Println(err == nil) // false

// Correct — return untyped nil
func getError() error {
    if bad {
        return &MyError{msg: "oops"}
    }
    return nil   // untyped nil → both type and value are nil
}

Goroutine leaks

A goroutine that blocks forever (waiting on a channel that is never written to, or a context that is never cancelled) is a leak. Leaks accumulate over the lifetime of a long-running service. 

// Wrong — goroutine leaks if caller forgets to close ch
func process(ch <-chan int) {
    go func() {
        for v := range ch {
            fmt.Println(v)
        }
    }()
}

// Correct — pass a context so the goroutine can be cancelled
func process(ctx context.Context, ch <-chan int) {
    go func() {
        for {
            select {
            case <-ctx.Done():
                return
            case v, ok := <-ch:
                if !ok { return }
                fmt.Println(v)
            }
        }
    }()
}

Loop variable capture in closures

Before Go 1.22, loop variables are shared across iterations. A closure that captures a loop variable sees only the last value of that variable. 

// Wrong (Go < 1.22) — all goroutines print the same value
for _, v := range []int{1, 2, 3} {
    go func() {
        fmt.Println(v) // captures the loop variable, not a copy
    }()
}

// Correct (Go < 1.22) — shadow the variable inside the loop
for _, v := range []int{1, 2, 3} {
    v := v // new variable per iteration
    go func() {
        fmt.Println(v)
    }()
}

// In Go 1.22+ this is fixed automatically — each iteration has its own variable.

Slice vs. array copy semantics

Slices are reference types: assigning a slice copies the header (pointer, length, capacity) but not the underlying array. Modifying elements of the copy modifies the original. 

// Surprising — b and a share the same backing array
a := []int{1, 2, 3}
b := a
b[0] = 99
fmt.Println(a[0]) // 99

// Correct — use copy() to get an independent slice
a := []int{1, 2, 3}
b := make([]int, len(a))
copy(b, a)
b[0] = 99
fmt.Println(a[0]) // 1

Forgetting to initialise a map

The zero value of a map is nil. Writing to a nil map panics. 

// Wrong — panic: assignment to entry in nil map
var counts map[string]int
counts["a"]++

// Correct — initialise with make
counts := make(map[string]int)
counts["a"]++

defer inside a loop

defer runs when the function returns, not when the block or loop iteration exits. Deferring inside a loop accumulates all defers until the function ends, which can exhaust file descriptors or hold locks longer than intended. 

// Wrong — all files stay open until processAll returns
func processAll(paths []string) {
    for _, p := range paths {
        f, _ := os.Open(p)
        defer f.Close() // deferred until processAll returns, not until iteration ends
        process(f)
    }
}

// Correct — wrap the body in a helper function
func processAll(paths []string) {
    for _, p := range paths {
        processOne(p)
    }
}

func processOne(path string) {
    f, err := os.Open(path)
    if err != nil { return }
    defer f.Close() // now defers until processOne returns
    process(f)
}

Losing error context

Returning a bare error discards the context of where it occurred. Use fmt.Errorf("...: %w", err) to wrap errors with context while keeping the original inspectable with errors.Is / errors.As. 

// Wrong — caller cannot tell what failed
func readConfig(path string) (Config, error) {
    data, err := os.ReadFile(path)
    if err != nil {
        return Config{}, err // context lost
    }
    // ...
}

// Correct — wrap with %w to add context and preserve the original
func readConfig(path string) (Config, error) {
    data, err := os.ReadFile(path)
    if err != nil {
        return Config{}, fmt.Errorf("readConfig %s: %w", path, err)
    }
    // ...
}

Ignoring channel direction in function signatures

Specifying channel direction (<-chan, chan<-) in function parameters makes intent explicit and lets the compiler catch misuse. 

// Imprecise — accepts both send and receive channels
func consume(ch chan int) { ... }

// Correct — declare only the operations this function needs
func consume(ch <-chan int) { ... } // receive-only
func produce(ch chan<- int) { ... } // send-only

Copying a sync.Mutex

sync.Mutex (and all sync types) must not be copied after first use. Embedding a mutex in a struct and then copying the struct copies the mutex state, which breaks its invariants. 

// Wrong — copying the struct copies the mutex
type Counter struct {
    mu    sync.Mutex
    value int
}

func cloneCounter(c Counter) Counter {
    return c // copies the mutex — race conditions ahead
}

// Correct — use a pointer receiver and never copy
func cloneCounter(c *Counter) *Counter {
    c.mu.Lock()
    defer c.mu.Unlock()
    return &Counter{value: c.value} // fresh mutex, copied value
}

Unnecessary string↔[]byte conversions in hot paths

Each string(b) or []byte(s) allocates. In hot paths, use strings.Builder, bytes.Buffer, or the unsafe package (with care) to avoid allocations. 

// Slow — allocates a new string on every iteration
for _, b := range data {
    process(string(b))
}

// Better — convert once outside the loop, or redesign to operate on []byte
func process(b []byte) { ... } // accept []byte directly

Type constraints vs. type sets (generics)

In Go generics, a constraint defines a type set — the set of types a type parameter may be instantiated with. A constraint interface can only be used as a type parameter constraint, not as a regular interface value. 

// Wrong — cannot use a constraint interface as a variable type
type Number interface {
    ~int | ~float64
}

var n Number = 42 // compile error: interface contains type constraints

// Correct — use the constraint only as a type parameter bound
func Sum[T Number](values []T) T {
    var total T
    for _, v := range values {
        total += v
    }
    return total
}
