Concurrent Worker Pool

Process a stream of jobs in parallel with goroutines, channels, and context-based cancellation.

What you'll build

A worker pool that:

  • Spins up N workers that each pull from a shared jobs channel
  • Collects results from a results channel
  • Cancels all workers cleanly when the context is done
  • Tracks total throughput with an atomic counter

main.go

package main

import (
	"context"
	"fmt"
	"math/rand"
	"sync"
	"sync/atomic"
	"time"
)

type Job struct {
	ID    int
	Input int
}

type Result struct {
	JobID  int
	Output int
	Worker int
}

// worker pulls jobs from the jobs channel until it is closed or ctx is done.
func worker(ctx context.Context, id int, jobs <-chan Job, results chan<- Result, wg *sync.WaitGroup) {
	defer wg.Done()
	for {
		select {
		case <-ctx.Done():
			return
		case job, ok := <-jobs:
			if !ok {
				return
			}
			// Simulate variable-duration work.
			time.Sleep(time.Duration(rand.Intn(50)) * time.Millisecond)
			results <- Result{
				JobID:  job.ID,
				Output: job.Input * job.Input,
				Worker: id,
			}
		}
	}
}

func main() {
	const (
		numWorkers = 5
		numJobs    = 20
	)

	ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
	defer cancel()

	jobs := make(chan Job, numJobs)
	results := make(chan Result, numJobs)

	// Start workers.
	var wg sync.WaitGroup
	for i := range numWorkers {
		wg.Add(1)
		go worker(ctx, i+1, jobs, results, &wg)
	}

	// Send jobs then close the channel so workers know when to stop.
	for i := range numJobs {
		jobs <- Job{ID: i + 1, Input: i + 1}
	}
	close(jobs)

	// Close results once all workers are done.
	go func() {
		wg.Wait()
		close(results)
	}()

	// Collect results.
	var processed atomic.Int64
	for r := range results {
		processed.Add(1)
		fmt.Printf("job %2d → %4d  (worker %d)\n", r.JobID, r.Output, r.Worker)
	}

	fmt.Printf("\nprocessed %d jobs with %d workers\n", processed.Load(), numWorkers)
}

Try it

go run main.go

Notice that jobs complete out of order — that's concurrency at work. Try changing numWorkers to 1 to see sequential processing.

Key concepts

Fan-out with a shared channel
Multiple goroutines reading from the same channel naturally load-balance: each job is picked up by whichever worker finishes first.
Closing channels as a signal
close(jobs) is how the producer tells workers there is no more work. The ok value in job, ok := <-jobs is false when the channel is closed and empty.
Context cancellation
The select inside each worker checks ctx.Done() first, so a timeout or explicit cancel propagates to all goroutines instantly.
sync/atomic
atomic.Int64 lets multiple goroutines increment a counter without a mutex — ideal for simple counters on the hot path.
